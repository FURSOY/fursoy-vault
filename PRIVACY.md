# Privacy policy

Effective date: August 13, 2026

FURSOY Vault is designed to operate locally. It does not collect telemetry, create an online
account, sell personal information, or send vault contents to the project maintainer.

FURSOY Vault's use of information received from Chrome APIs adheres to the Chrome Web Store User
Data Policy, including the Limited Use requirements. It uses this information only to provide the
user-requested local session-protection feature.

## Data processed on the device

FURSOY Vault processes only the information needed to protect sites selected by the user:

- the domains the user chooses to protect and their protection policies;
- cookies belonging to those domains, including cookie values and browser cookie attributes;
- a random identifier for each regular Chrome profile so profiles remain isolated;
- local controller state such as lease status, permission status, and timestamps;
- the browser's active, idle, or locked state used to apply the selected locking policy;
- redacted security and reliability audit events; and
- local Chrome process command lines only long enough to detect supported risk indicators such as
  a remote-debugging launch. Raw command lines are not written to the audit log.

Cookie values are transferred only between Chrome and the locally installed FURSOY Vault companion
through Chrome Native Messaging. They are stored in the current Windows user's local application
data directory in an encrypted vault. Extension storage contains controller metadata, not vaulted
cookie values.

Windows Hello is handled by Windows. FURSOY Vault receives a cryptographic assertion and public
credential information; it does not receive or store fingerprints, facial images, a Windows PIN,
or other biometric data.

## Network transfers

FURSOY Vault does not transmit vault contents, cookie values, protected-site lists, browsing
history, Windows Hello data, audit events, or monitoring results to FURSOY, SignPath, or any other
project-operated server.

The extension opens a GitHub download URL only when the user requests the companion installer.
Visiting GitHub, the Chrome Web Store, or a protected website is governed by that service's own
privacy policy. Normal traffic between Chrome and a protected website is generated by Chrome and
the website, not collected by FURSOY Vault.

## Chrome permissions

FURSOY Vault uses Chrome permissions for these local functions:

- `cookies` and user-approved optional site access: capture, remove, and restore cookies only for
  sites the user explicitly protects;
- `nativeMessaging`: communicate with the locally installed companion;
- `storage`: keep non-secret settings and controller state;
- `idle`, `alarms`, and `webNavigation`: enforce the selected locking policy;
- `activeTab`: identify the current site when the user opens the extension; and
- `notifications`: report important local protection or permission states.

Site access is requested per protected domain and can be revoked through Chrome.

## Retention and deletion

Removing a protected site deletes that site's local vault record. Redacted audit events are kept
for up to 90 days. Removing the Chrome extension clears its Chrome-managed local storage but does
not silently delete the companion's encrypted vault files.

The companion uninstaller disables Native Messaging while preserving vault data by default so an
accidental uninstall is reversible. Running `uninstall.ps1 -Purge` permanently removes the
companion and all FURSOY Vault data under `%LOCALAPPDATA%\FursoyVault`.

## Sharing and third parties

FURSOY Vault does not share user data with advertisers, analytics providers, data brokers, the
project maintainer, or any other third party. Published build artifacts do not contain any user's
vault or browser data.

## Changes and contact

Material changes to this policy will be committed to the public source repository. Privacy
questions and security reports can be submitted through the repository's GitHub issue tracker.
